# Render graphs

`Modifier.drawBackdrop` creates independently sampled and composited images using receiver-owned
`GraphicsLayer` objects. Use [styled surfaces](styles-and-decorations.md) for fixed-order appearance
and `surface { }` for optical and drawing declarations within surface phases. Graph operations
keep intermediate pixels in native graphics resources. The declaration runs under snapshot
observation; read animated state there or in drawing callbacks to avoid recomposition.

## Declare operations in order

Image operations select or composite into `current`. `source()` selects the original input,
`replace(image)` selects an earlier result, and `draw(image)` composites a result over the current one. `image { }` captures
a reusable subgraph without changing the surrounding result. It starts transparent; call `source()`
inside it when processing the backdrop. `group { }` starts transparent and replaces the surrounding
result with its completed composite. Its alpha applies once to the whole group.

```kotlin
Modifier.drawBackdrop(backdrop, shape = { shape }) {
    val glass = image {
        source()
        effects { blur(16.dp.toPx()) }
        clipSurface()
    }
    group {
        shadow(Shadow.Default)
        draw(glass)
        fill(tint)
        highlight(Highlight.Ambient, colorSource = glass)
    }
}
```

The root `BackdropRenderScope` selects the background, `foreground { }`, and `export(image)`.
`foreground { }` replaces the selected foreground. `appendForeground { }` builds an additional image
from transparent pixels and composites it above the retained foreground. Root `styledSurface(style)` owns its fixed foreground
and rejects replacement or another surface owner. Its independent style-construction DSL and fixed
rendering contract are described in [Styles and decorations](styles-and-decorations.md).

Nested declarations receive `BackdropImageScope`. DSL markers prevent accidental implicit access
to outer graph operations from drawing, effect, and nested image receivers. These mutable scopes
are declaration builders that close when resolution begins. Their `density` is an immutable
conversion context; use `with(density) { distance.toPx() }` in graph geometry and ordinary
`dp.toPx()` inside drawing or effect callbacks.

`layers { backdropLayer(image) { alpha = .5f } }` replaces current with an ordered transparent-based
composite. The list and layer builders are generated by dsl-utilities; they snapshot configurations.
Images can be reused within their declaration; references from another declaration are rejected.

## Extend the declaration language

Effect entry points are extension functions in their owning packages. Import `highlight` from
`top.ltfan.backdrop.highlight`, `shadow` and `innerShadow` from `top.ltfan.backdrop.shadow`, and
`interactionLight` from `top.ltfan.backdrop.interaction`. Highlight direction declarations `angles`
and `incidence` are extensions in the highlight package.

User extensions operate on the same public scopes:

```kotlin
import androidx.compose.ui.unit.Dp
import top.ltfan.backdrop.BackdropImageScope
import top.ltfan.backdrop.effects.blur

fun BackdropImageScope.glass(radius: Dp) {
    source()
    effects { blur(radius.toPx()) }
    clipSurface()
}
```

An extension can compose image operations, capture reusable branches, or configure a highlight
through `HighlightScope` and `HighlightAngleScope`. The DSL marker limits implicit access to outer
receivers inside nested declarations. The renderer owns scope creation, graph nodes and layer
lifecycle; custom operations use the public drawing, effect-registration and
[primitive contracts](custom-primitives.md).

## Process and paint

`effects { }` runs serial effects on current. `paint { }` draws after current; `paintSurface { }`
clips only the appended drawing to the visible surface. Both painting callbacks receive
`BackdropRoom`, which describes surface size and sampling extension. Brush sizing uses the surface size, independently of storage margins.

Painting defaults to `CompositingStrategy.Offscreen`, so destination-based operations such as
Clear affect only the resulting graph image. For appended SrcOver drawing, pass
`compositingStrategy = CompositingStrategy.Auto` to compose into the consumer without forcing a
separate paint buffer. Import `CompositingStrategy` from `androidx.compose.ui.graphics.layer`.
The callback owns this choice: Auto drawing must preserve the consumer's existing destination.
Graph alpha, masks and blend operations still apply to the complete image.

```kotlin
source()
effects { blur(12.dp.toPx()) }
clipSurface()
paintSurface { drawRect(tint) }
```

`clip(shape)`, `clip(path)` and `transform(matrix)` transform current. `clipSurface()` uses the
receiver shape extended by visible insets and effect coverage. `drawWithContent { drawContent,
room -> }` controls whether and how to include its input. Declare its complete sampling footprint
when sampling transformed positions; omitting `drawContent()` replaces input drawing.

## Coverage and erasure

`mask(coverage)` multiplies current by an image's alpha. `BackdropMaskChannel.Luminance` uses
premultiplied working-space RGB weights 0.2126, 0.7152, 0.0722 and requires runtime shader support.
`inverse = true` reverses coverage. Alpha masks use layer compositing directly.

`clear(rect)` and `clear(path)` erase current in an isolated intermediate, revealing whatever is
behind the receiving surface. Drawing a transparent rectangle with SrcOver does not erase pixels;
use `BlendMode.Clear` or these helpers. `BackdropFill` describes painted tint and optional ramp
choices for consumers; a fill does not control transparency of already processed input.

## Compose independent blur regions

`mix(first, second, weight)` replaces current with a premultiplied interpolation. The weight can
be a scalar or an image's alpha. It differs from drawing one translucent image over another.

```kotlin
val near = image {
    source()
    effects { blur(4.dp.toPx()) }
    clipSurface()
}
val far = image {
    source()
    effects { blur(20.dp.toPx()) }
    clipSurface()
}
val weight = image {
    paint { drawRect(Brush.verticalGradient(listOf(Color.Transparent, Color.White))) }
}
mix(near, far, weight)
val material = current
highlight(Highlight.Default, colorSource = material)
```

Add independent branches and weight images for more transitions. To accumulate processing,
select a preceding image with `replace` inside the next branch.
The portable custom shader interface accepts one rendered input, so composite branches into one
image before applying a custom shader.

## Primitives and presentation

`highlight`, `shadow`, `innerShadow`, and `interactionLight` append primitives at their declaration
position. They can coexist inside one image or occupy separate captured images. Primitive
configuration controls its response; statement `alpha` and `blendMode` control external composition.
Interior interaction light defaults to additive `BlendMode.Plus`. A decoration's `None` omits its
node and resources; a zero-alpha configuration has transparent output.

```kotlin
Modifier.drawBackdrop(backdrop, shape = { shape }, backgroundAlpha = { alpha.value }) {
    source()
    effects { blur(8.dp.toPx()) }
    clipSurface()
    val material = current
    highlight(Highlight.Default, colorSource = material)
    export()
    foreground { innerShadow(InnerShadow.Default) }
}
```

`backgroundAlpha` applies once to the complete background, leaving children and foreground alone.
At zero, background recording is skipped; an explicitly exported result is recorded transparent.
`export()` selects current at that point; passing another image selects it explicitly. The selected
image is exported with `backgroundAlpha` applied. Its visible bounds are rounded outward to whole
pixels in layer-storage coordinates; unused sampling padding is excluded. See
[exported source domains](sources-and-surfaces.md#export-a-processed-surface). Foreground starts transparent and is
drawn after children. Exported pixels exclude children unless the source itself contains them.

`BackdropRenderStyle` supplies inherited `render` and `insets` producers to graph receivers. An
explicit render declaration replaces the inherited one completely; its `NoEffects` is an empty
render declaration that leaves the original input selected. For a serial effect chain and fixed
decoration phases, use [the surface DSL](styles-and-decorations.md).

## Compose progressive blur alternatives

`layeredProgressiveBlur` operates on the current image, independently blurring it at several radii
before mixing adjacent levels. It belongs to the image DSL because it needs branches and masks;
`effects { progressiveBlur(...) }` remains the runtime-shader algorithm in a serial effect chain.
Both share ramp geometry and leave alpha fading to the caller. The `mask` and `mix` operations
can instead fade a uniform blur or interpolate it with the original image. See
[Effects and sampling](effects-and-sampling.md#choose-a-progressive-blur-algorithm) for caller-selected
routes, capability requirements and examples.

## Drawing outside a modifier

`BackdropRenderScope` can be constructed with a `Density`, surface-pixel `Size`, `Shape` and
`LayoutDirection`. Its optional style producer supplies inherited appearance. Build the same DSL
used by `drawBackdrop`, then pass the declaration and requested surface bounds to
`BackdropRenderer.resolve`. Resolution seals the declaration; build a new declaration to change
its structure. Effect inputs may be resolved again on the existing declaration.

The renderer owns its native layers and primitive resources. Keep its graphics context alive and
use it on that context's drawing thread. Call `beginFrame` after resolution or `refresh`, and when
source or drawing inputs change. `prepare` records a selected output without presenting it;
`draw` presents it. Repeated draws in the same frame reuse recordings. Both accept the background
by default, or the handles selected as `foregroundImage` and `exportedImage`. Use `outputBounds`
to inspect a reachable image's visible bounds. Image handles belong to their declaration.

```kotlin
val declaration = BackdropRenderScope(density, size, shape, layoutDirection).apply {
    surface {
        effects { blur(12f) }
    }
}
BackdropRenderer { graphicsContext }.use { renderer ->
    renderer.resolve(declaration, Rect(Offset.Zero, size))
    renderer.beginFrame()
    renderer.draw(target) { requested -> drawSource(requested) }
}
```

Here `target` is a `DrawScope` with the declaration's density and layout direction. The source
callback draws the requested sampling footprint in surface coordinates. The host owns finite-source
tiling, snapshot observation, invalidation, presentation opacity and window coordinate mapping.
Modifier rendering additionally integrates window interaction lighting; independent declarations
use their explicit effects and decorations. `close` releases resources and declaration references,
is repeatable, and allows reuse after a fresh successful `resolve`. A failed resolution also
requires a successful resolution before drawing again. Close the renderer before replacing its
graphics context. These drawing objects expose unsignalled mutable state, so they carry no Compose
stability annotation.
